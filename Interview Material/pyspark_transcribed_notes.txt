Job:
A Spark job is a unit of work that Spark executes when you call an action.

In short:
- When you run an action, Spark creates a job.
- Job -> triggered by action.
- Stage -> group of operations.
- Task -> smallest unit that runs on one partition.

Flow:
Code -> Driver -> DAG -> Job -> Stage -> Task -> Result.

DAG:
- Directed Acyclic Graph.
- A plan is Spark's execution plan that shows how data moves from input to output through transformations.

Spark operations are divided into two types:
1. Transformation
   - Where you want to transform the data.
   - Examples: select, filter, orderBy, groupBy.

2. Action
   - Where you want to get the result.
   - Examples: write, show, count, collect, commit.

Note:
- If a Spark operation returns a result, it is an action.
- Otherwise it is a transformation.

Transformation types:
1. Narrow transformation
   - Data stays in the same partition.
   - Faster.
   - No shuffle.
   - Examples: filter, select.
   - If transformation is applied row-by-row on one partition, it is a narrow transformation.

2. Wide transformation
   - Data moves across partitions.
   - Shuffle happens.
   - Slower.
   - Examples: orderBy, groupBy.
   - In wide transformation, you cannot process alone; data is collected across partitions.

Data Skewness:
Data skewness means data is unevenly distributed across partitions, causing some tasks to process much more data than others.

Example:
- Country column with majority of data from India and fewer rows from other countries.
- Heavily partitioned data can take more time on wide transformations and slow jobs.

How to fix skew/repartition:
- df2 = df.repartitioning(5)
- Or df.repartitioning(10, "country")
- Evenly distributed data helps reduce time to process partitions.

Repartitioning vs Coalesce

Repartitioning:
- Redistributes data evenly across partitions using shuffling.
- Can increase or decrease partitions.
- Causes shuffle.
- Expensive due to shuffle.
- Slow.

Coalesce:
- Reduces partitions without shuffle by combining partitions.
- No shuffle happens.
- Faster.

Cache vs Persist

cache():
- Stores the dataframe/RDD in memory (RAM) for reuse.
- Faster.
- May fail if data does not fit in memory.
- df.cache()

persist():
- Provides an option to choose how data is stored:
  - memory only
  - memory and disk
  - disk only, etc.
- Safer than cache because it can use disk if memory is insufficient.
- df.persist()

Serialization:
- Serialization is the process of converting data into a byte format to reduce memory usage and enable efficient data transfer.
- Compressed form.

Deserialization:
- Means converting serialized data (byte format) back into usable objects.

Join:
- A join combines rows from two tables or DataFrames based on a common column/key.

Syntax:
df.join(df2, "condition", join_type)

Join types:
- Inner: returns only matching rows from both tables.
- Left: all rows from left and matching rows from right.
- Right: all rows from right and matching rows from left.
- Full outer: all rows from both tables, matched or unmatched.
- Left semi join: returns only matching rows of left table.
- Left anti join: returns left table rows unmatched from right table.
- Cross join: most expensive.

Broadcast join:
- Broadcast join is a join optimization where Spark sends a small table to all executors.
- The join happens locally without shuffling a large table.
- Why used: to avoid shuffle because shuffle is expensive and time taking.
- When used: when one table is small enough to fit in memory.
- Customizable threshold.

Broadcast join import:
from pyspark.sql.functions import broadcast

Syntax:
df.join(broadcast(df2), df.id == df2.id)

Limitation:
- Whenever broadcast join happens, out-of-memory problems can occur because if table is large in size, it cannot hold the whole dataframe.

Optimization:
- Partition based on id.
- Sort-merge join.
- Sort-merge join is a technique where Spark first sorts tables on the join key and then merges them to produce results.

Example:
df1 = df1.repartition(partitions, "id")
df2 = df2.sortWithinPartitions("id")

join_df = df1.join(df2, df1.id == df2.id)
display(join_df)

Bucketing:
- Bucketing is a technique of dividing a table or dataset into a fixed number of files/buckets based on a column's hash value to improve query performance.

Example:
df.write \
  .bucketBy(10, "customerid") \
  .sortBy("transaction_date") \
  .saveAsTable("bucketed_transactions")

Note:
- If you want to join, the number of buckets in both DataFrames must be the same.
- Plan/output shows partitions.

AQE - Adaptive Query Execution:
- Adaptive query execution in Spark dynamically optimizes query plans at run time by handling skew, coalescing partitions, and switching join strategies to improve performance.

Types of activity in ADF:
1. Copy activity
   - Used to move data from source to destination.

2. Data Flow
   - Used for complex transformations like joins, transformations, aggregations, deduplication, schema changes.

3. Stored Procedure
   - Execute business logic inside a database.

4. If Condition
   - Run activity based on condition.

5. For Each
   - Used for iteration.

6. Switch
   - Execute different logic for different values, like case statement.

7. Execute Pipeline
   - Call one pipeline from another pipeline.

8. Wait Activity
   - Pause pipeline for a fixed interval.

9. Until Activity
   - Repeat execution until a condition is met.
   - Used for polling scenarios like checking file arrival.

10. Web Activity
   - Call REST APIs.
   - Used to interact with external systems.

11. Get Metadata
   - Fetch file information like file exists, size, and last modified.

12. Lookup Activity
   - Read small reference data or configuration values.

13. Fail Activity
   - Explicitly fail a pipeline with custom message/condition.
   - Stop the pipeline and mark it as failed when condition is not met.

High Watermark Concept for incremental load:
- Lookup -> read date from high watermark file.
- Lookup -> read max last modified date.
- Copy -> fetch records between two dates / from source.
- Copy -> update high watermark file by last modified date.

ADF components:
- Pipeline
- Activity
- Dataset
- Linked service
- Triggers
- Integration runtime

If Condition vs Switch:
- If Condition handles binary logic.
- Switch handles multiple cases.

Retry Policy:
- Automatically retries failed activity executions based on configured count and interval.

How Spark processes data:
- Spark processes data by splitting it into smaller parts and processing them in parallel.
- When we write Spark code, the driver first understands the logic and prepares a plan.
- Execution starts only when an action is called.
- Spark distributes the data across executors.
- Each executor processes its partition.
- The final result is written or returned.

Spark planning process:
User code -> Unresolved logical plan -> Analyzer -> Resolved logical plan -> Optimized logical plan.

Diagram notes:
- Syntax/analysis.
- Catalog.
- Metadata (data about data).
- Query check.
- Final optimized plan.

Physical plan:
- Optimized logical plan -> physical plan candidates.
- Cost model chooses best physical plan.
- Executed on cluster.
- Example: physical filtering process.

In my project, we built an end-to-end data engineering pipeline on Azure using a metadata-driven framework based on medallion architecture.

We ingested data from multiple legacy and cloud sources into ADLS using Azure Data Factory, Databricks Auto Loader, and Databricks.
